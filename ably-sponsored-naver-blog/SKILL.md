# 목표

확인된 사실을 작성자의 실제 관심·경험과 연결해 평소 네이버 블로그 글처럼 쓴다. 광고 문장을 구어체로만 포장하지 않는다.

우선순위는 `현재 요청·수정 피드백 > 미션 필수사항 > 이 스킬 > 공개 참고 글의 경향`이다. 다른 글의 문장, 도입, 상품 순서, 감탄사, 오탈자를 복제하지 않는다.

# 작업 흐름

1. 첨부 파일, 미션 가이드, 사진, 상품 페이지, 기존 원고를 먼저 읽는다.
2. 내부적으로 다음을 정리한다. 요청받지 않으면 출력하지 않는다.
   - **미션 계약:** 표시 문구와 위치, 키워드와 횟수, 기간·가격·할인율, 이미지, 개인 링크, 분량·줄바꿈.
   - **근거 장부:** 상품별 `실제 구매·사용·방문 / 주문만 완료 / 사진 관찰 / 공식 정보 / 확인된 취향 / 기대`.
3. 글을 `실사용 후기 / 미사용 큐레이션·행사 / 방문·서비스 체험 / 혜택 안내` 중 하나로 잡되 상품별 근거는 따로 판정한다.
4. 실제 계기나 선택 기준을 중심으로 작성한다.
5. 사실, 표시, 키워드, 링크, 문체를 검수한다.

자료에 없는 사실은 일반 지식으로 메우지 않는다. 외부 조사는 요청받은 경우에만 하며 제공 자료와 구분한다. 누락 정보는 추측하지 말고 선택적 내용은 생략한다. 표시 문구나 개인 링크처럼 게시를 막는 값만 `[확인 필요: 항목]`으로 남긴다.

# 사실과 기대

- 직접 했다고 확인된 범위에서만 구매·사용·방문, 맛, 착용감, 발림, 지속력, 성능을 확정한다.
- 주문만 했다면 주문 사실과 고른 이유까지만 쓴다. 시식·사용 후기는 만들지 않는다.
- 사진에서는 색, 형태, 구성, 양, 길이, 디테일처럼 보이는 것만 말한다.
- 공식 자료에서는 수치, 소재, 구성, 기간, 가격, 배송, 공식 기능만 가져온다.
- 기대는 `~해보고 싶다`, `~와 잘 어울릴 것 같다`처럼 기대임을 드러낸다.
- 같은 상품에서 실제 경험과 기대 시제를 섞지 않는다. 제목의 `후기`도 체험을 지어낼 근거가 아니다.

# 구조와 문체

- **제목:** 검색 주제 + 상품·행사명 + 실제 차별점 하나. 같은 뜻의 키워드를 나열하지 않는다.
- **도입:** 2~4문장. 실제 계기나 선택 기준부터 시작하고 범용 날씨·가상 고민·형식적 인사말은 생략한다.
- **행사형:** 생활 맥락 → 필수 혜택 → 개인 링크 → 고른 상품.
- **후기형:** 사용 전 상황 → 실제 과정 → 조건이 드러나는 체감 → 맞는 사용 상황.
- **상품 블록:** `브랜드명 + 상품명 소제목 → 이미지 → 1~2개 짧은 문단 → 개인 링크`. 소제목의 상품명을 첫 문장에서 반복하지 않는다.
- 상품 하나에는 `구체적 특징 / 실제 선택 이유 / 사용·기대 장면 또는 실제 결과` 중 근거 있는 두 요소면 충분하다.
- 한 문단은 한 가지 이야기만 1~3문장으로 쓴다. 문장 길이와 종결어미를 기계적으로 반복하지 않는다.
- 추상적 칭찬보다 명사, 수치, 형태, 조건, 생활 장면을 쓴다. 화면을 중계하지 않는다.
- 확인된 불편은 조건과 범위를 붙여 쓸 수 있지만, 신뢰감을 위해 단점을 만들지 않는다.
- CTA와 링크 안내는 글 전체에서 한 번이면 충분하다. 이모지·엔터·Markdown은 현재 요청과 기존 원고를 따른다.

# 제거할 패턴

- 하지 않은 구매, 사용, 방문, 클릭, 장바구니, 배송 대기, 반복 사용, 취향.
- `핵심 포인트`, `가장 큰 장점`, `전반적으로`, `활용도가 높다`, `합리적인 선택`, `추천드립니다`만으로 이루어진 평가.
- 모든 상품의 `첫인상 → 장점 나열 → 추천 대상 → CTA` 반복.
- `역대급`, `무조건`, `인생템`, `완벽`, `맛이 없을 수 없다`, `최고` 같은 근거 없는 과장.
- 성분·소재·재료만 보고 건강, 다이어트, 피부 개선, 체형 보정, 안전성을 단정하는 문장.
- 확인되지 않은 단점, 반복 구매 유도, 다른 블로그나 미션 예시의 문장·도입·상품 순서 복제.

추상어를 다른 추상어로 바꾸지 말고 **어떤 특징이 어떤 상황에서 의미가 있는지** 쓴다.

# 준수와 출력

- 경제적 이해관계는 미션의 정확한 문구와 위치를 따른다. 임의로 약화하거나 바꾸지 않는다.
- 필수 키워드는 지정된 형태와 횟수만 지키고, 사용자의 개인 링크만 넣는다.
- 상품명, 가격, 기간, 할인율, 수치, 이미지, 링크를 원자료와 대조한다.
- 완성 원고 요청에는 장황한 분석 없이 게시 가능한 제목과 본문을 출력한다.
- 수정에서는 확인된 사실, 수치, 링크, 표시 문구, 사용자의 고유 경험을 보존한다.
- `[확인 필요: ...]`가 있으면 원고 뒤 한 줄에만 모으고, 본문에는 근거 분류나 분석 메모를 넣지 않는다.

빠른 검수에는 `references/quick-checklist.md`, 경계 사례에는 `references/style-guide.md`를 읽는다. 원고가 파일이면 선택적으로 다음을 실행한다.

```bash
python3 scripts/check_draft.py <draft.md> \
  --require "<정확한 표시 문구>" \
  --require "<개인 링크>" \
  --require-count "<필수 키워드>=<횟수>"
```

검사 결과는 보조 신호다. 실제 경험으로 확인된 표현까지 기계적으로 삭제하지 않는다.
